# Сопоставление карты — #43

Исследовательский прототип на Python и OpenCV: измеряет точность, долю успешных сопоставлений и время обработки кадров. Результаты помогут оценить 15–30 кадров/с при CPU < 5%. Для продукта алгоритм будет переписан на Rust.

Тайлы Kongying нужны только для локальных замеров. Лицензии на эти данные нет: файлы остаются в `.cache/`, который указан в `.gitignore`, и не коммитятся. Скриншоты тестера тоже не кладём в репозиторий: на них есть UID.

## Запуск

Нужны Windows 11, Python 3.14, `opencv-python` 5.0.0 и numpy.

```sh
pip install -r apps/overlay/research/map-match/requirements.txt
python apps/overlay/research/map-match/fetch_ref.py --zoom 11
python apps/overlay/research/map-match/match.py --ref .cache/map-ref/ref_z11.png --shots "<папка 1080>" "<папка 1600>" --synthetic 50
```

Итоги — в `.cache/map-match-out/report.md`. Отпечатки кадров — в `footprints.jpg`, наложения для проверки глазами — в `debug/`; там же рядом с отчётом лежит `report.json`.

## Склейка (stitch.py)

```sh
python apps/overlay/research/map-match/stitch.py --ref .cache/map-ref/ref_z11.png --shots "<папка 1080>" "<папка 1600>::160,39,1600,993" --only "ли юэ|liyue|карт|map " --tiles
```

В `.cache/map-stitch/` появятся мозаика с альфой, карта покрытия, сравнение и `stitch.json`.
Флаг `--tiles` добавляет тайлы уровней `zoom`–`zoom-3` с глобальными индексами.
Эталон служит для привязки и локального сравнения; пиксели мозаики берутся из скриншотов.

## Результаты (19.10.2026)

Прогон: эталон `tiles_twt672` z11 (7680×6656), скриншоты тестера — 37 шт. в 1080p (ru, полный экран) и 29 шт. в окне 1600 px (en), плюс 50 синтетических кадров. ПК на 12 ядер, замеры в один поток.

**SIFT** (выбран):

| Что | Результат |
| --- | --- |
| Карта, поверхность, отдалено / средне | 12/12 и 12/12 |
| Карта, поверхность, максимально приближено | 9/12: при этом масштабе 1 px z11 ≈ 7 px экрана, деталей мало — нужен эталон z12–z13 |
| Древняя священная гора | 0/2: этой области нет в `tiles_twt672`, у неё отдельный слой |
| Подземелья, Энканомия, разлом | 0/7: на эталоне поверхности их нет, нужны свои слои |
| Миникарта, глобальный поиск | 2/10: круг маленький и повёрнут; для #46 нужен локальный поиск от известного положения |
| Синтетика | 36/50; провалы — кадры почти целиком из моря |
| Точность | репроекция ≈ 0.1 px z11; синтетика: медиана 0.7 px z13, p95 2.5 px z13 |
| Время | глобально ≈ 1.6 с на кадр; локально (окрестность известна) ≈ 1.5 с на полном кадре и ≈ 0.6 с на половинном: детекция признаков на кадре съедает всё время |

**ORB** хуже во всём: на поверхности 17/48, приближенные кадры 0/12, глобально ≈ 3.5 с.

Масштаб карты в игре (px эталона z11 на px экрана) одинаков в 1080p и в окне: отдалено 0.855, средне ≈ 0.43–0.52 (колёсико плавное), приближено 0.143–0.150.

**Слежение кадр-к-кадру** фазовой корреляцией (`cv2.phaseCorrelate`, кадр уменьшен до 480×270): ≈ 7 мс на кадр вместе с уменьшением 1080p, ошибка сдвига 0.3 px экрана (p95 0.5).

## Вывод

Сопоставлять признаки на каждом кадре нельзя: SIFT при 15 кадрах/с — около 87% всех 12 ядер, это в сотни раз больше бюджета. Схема для #45–#47:

1. Карта открылась — один глобальный поиск SIFT (≈ 1.5 с, в фоне; позже ускорить: эталон с признаками заранее, грубый поиск по уменьшенному кадру).
2. Дальше — слежение фазовой корреляцией между соседними кадрами: ≈ 7 мс × 15 кадров/с ≈ 10% одного ядра ≈ 1% от 12 ядер. Если кадр не изменился (карту не двигают), не считать вовсе.
3. Изменение масштаба (колёсико) ломает чистый сдвиг — при падении отклика корреляции делать локальный SIFT по окрестности и раз в несколько секунд сверяться с эталоном.

15–30 кадров/с при CPU < 5% реальны только по такой схеме. Для приближенного масштаба эталон нужен z12–z13; подземелья и Древней священной горы в `tiles_twt672` нет — их тайлы придётся собирать отдельно (по решению #48 мы и так склеиваем свои тайлы из скриншотов).
